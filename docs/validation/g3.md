# G3 动画、解码与过渡

2026-10-18，build 18 集成实现；自动检查通过，真实宿主画面尚待验。

## 已实现

- 沿用 G1 实测可用的原生 ScreenSaverView 入口、首次 start 分类和单次不透明背景重绘。图片由 Core Graphics 同帧合成，避免此前移动子图层的残留；没有改用私有扩展或独立全屏 App。渲染实现按 G1 证据从最初 CA 动画方案调整，仍使用公开原生框架。
- 以 CACurrentMediaTime 单调时间驱动，默认 5 秒启动下一张、1.5 秒上层渐入，底层始终不透明，两张各自持续运动。下一张未准备好时保持旧画面，实际入场后重建基准；F=0 直接切换。
- 填充基准额外留 2 个 backing pixel 余量，起点缩放 1，终点从 1.10–上限随机选取，中心偏移受当前尺寸可用范围约束。尺寸与偏移共用线性进度，两个端点满足覆盖且各边界差为线性函数，所以中间也覆盖。
- ImageIO 降采样、EXIF 归一化、HEIF 主图/其他格式首帧、sRGB 不透明输出。实际含透明像素时用同图模糊填充背景，再放入完整前景；全透明内容有中性色兜底。
- 每视图最多当前/过渡/预加载三张；每张缓存像素 ≤8 Mi（32 MiB），全进程已解码图片预算 256 MiB。后台全局串行避免并行临时解码峰值。这是缓存边界，不等于宿主/GPU/临时内存上限；G4 仍须实测。

## 自动证据

`./scripts/test-core.sh`：10000 条确定种子路径，每条 101 个进度点（1010000 点），检查覆盖和比例；另测 1×1、极宽/极高、两个视口、backing 1/2、缩放下限、越界进度钳制。默认时间轴、1.5 秒重叠、零过渡、延迟解码和时间基准重建均通过。

`./scripts/test-decode.sh`：实际解码 JPG/JPEG、PNG、HEIC、WebP，验证 sRGB/不透明缓存；EXIF 1–8 同时检查方向尺寸与角点颜色；透明 PNG/WebP、坏图拒绝、异步坏图跨轮隔离、取消回写、缓存释放均通过。测试图为原创合成，生成器采用 MIT，存于 LocalPhotos，不是个人照片。格式成功仅证明普通进程 ImageIO 路径，A06 原生宿主证据仍待验。

构建默认 Release（-O），无新增产品依赖；Pillow 仅用于本地合成 WebP 等测试图。旧 build 16 已通过的 G1 证据保留，新播放器改变了生命周期及配置存储，受影响的原生宿主/配置/权限/重启需复核，不冒充完整产品验收完成。
